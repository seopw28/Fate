# 화면 배율 0.9 축소 제거 계획 (1.0 기준으로 다시 만들기)

- 브랜치: `refactor/ui-scale-1` (작업 폴더 `Fate/worktrees/blood-mana`), 시작점 main `5436578`
- 목표: `zoom:0.9`를 없애고, 1.0 배율에서 지금(0.9 축소)과 같은 크기로 보이게 한다.
- 왜: 화면은 0.9배로 그려지는데 효과 위치는 축소 전 좌표로 계산하는 곳이 섞여, 소환 마법진처럼 위치가 어긋나는 문제가 반복된다.

## 작업 규칙

- 한 단계는 짧게(대략 15분 이내) 끝낸다. 길어지면 멈추고 보고한다.
- 단계마다 아래 "확인"을 실제로 돌리고, 통과하면 체크하고 커밋한다(커밋 메시지에 단계 번호).
- 큰 일을 서브에이전트 하나에 통째로 맡기지 않는다. 오래 기다리는 백그라운드 실행을 하지 않는다.
- 전체 테스트(`npm test`, 약 2분)는 묶음 끝(1-4, 3-4, 5-3)에만 돌린다. 중간에는 그 단계의 검사만 돌린다.
- 묶음(1·2·3·4·5)이 끝날 때마다 PM에게 보고하고 다음 묶음으로 넘어간다.
- 3·4 묶음은 스타일 전체를 건드리므로, 시작 전에 PM에게 알리고 그동안 다른 세션의 목업 수정을 멈춰 달라고 한다.

## 현황 (2026-11-08 조사)

- 축소 위치: `styles.css` 1808~1814줄. `main.app`, `#collection-modal`, `#result`, `#tier-modal` 4곳에 `zoom:var(--ui-scale)`(0.9), 높이·너비는 `100vh / var(--ui-scale)`로 보정.
- `index.shell.html` 12줄: `?scale=0.6~1.2`로 배율을 바꾸는 스크립트.
- CSS: 2,129줄, px 값 약 4,650개, vw·vh 쓰는 줄 188개, rem 1개, `@media` 86개.

## 변환 원칙

축소가 걸린 4곳 안의 요소만 0.9배로 바꾼다. 축소 바깥(`body`에 바로 붙는 효과·토스트 등)은 지금도 1.0이므로 바꾸지 않는다.

| 값 | 축소 안 요소 | 축소 밖 요소 |
|---|---|---|
| px (3px 이상) | ×0.9 | 그대로 |
| px 1~2 (테두리·선) | 그대로 | 그대로 |
| vw·vh | ×0.9 (`/ var(--ui-scale)` 보정이 붙은 값은 보정만 제거) | 그대로 |
| rem | ×0.9 | 그대로 |
| %·em·숫자만(line-height 등)·각도·시간 | 그대로 | 그대로 |
| `@media` 기준값 | 그대로 (화면 너비 기준이라 축소와 무관) | 그대로 |
