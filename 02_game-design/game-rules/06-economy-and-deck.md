# 06. 경제, 소환(가챠), 덱 편성, 저장 데이터

> **덱 상점(카드 소환)은 실질 결제 창구가 될 예정입니다.** 아래 수치는 현재 프로토타입 값이며, 과금 설계 시 가장 먼저 재검토할 영역입니다.

## 1. 크래커 (재화)

| 구분 | 내용 | 값 |
|---|---|---|
| 시작 보유량 | 새 저장 데이터 | 300 |
| 무료 지급 | 스타트 팩 | 첫 진입 시 계정당 1회 · 0크래커 |
| 소모 | 카드 뽑기 1회 | 200 |
| 소모 | 카드 뽑기 10회 | 2,000 |
| 선택 | 성격 오라 | 0 |
| 획득 | PvC 클리어 | 고정 200 (상대 재화와 무관한 게임 보상) |

- 보유 크래커는 화면 상단 `◆ 크래커 N`에 표시되고 브라우저 저장소(localStorage)에 저장됩니다. 서버 연동·실결제는 아직 없습니다.
- 공개 목업에서는 상점·합성·강화 시연이 막히지 않도록 접속 시 크래커를 최소 1,000,000개, 쿠키조각을 최소 50,000개로 보충합니다. 이는 시연 전용이며 실제 서비스 경제 규칙이 아닙니다.
- 스타트 팩은 첫 진입 시 계정당 한 번 자동 지급하며 크래커를 차감하거나 유료 상품으로 판매하지 않습니다.
- 크래커는 **PvC 클리어 보상으로만** 늘어납니다 (자연 회복·일일 보상 없음). 상대가 보유한 재화를 빼앗거나 차감하는 시스템은 없습니다.
- 테스트용으로 주소 뒤에 `?crackers=10000`을 붙이면 보유량을 그 값으로 맞춥니다. **개발 환경(localhost 등)에서만 동작**하며 배포 주소에서는 무시됩니다 → [08](08-controls-and-dev.md).
- ⚠ 크래커는 브라우저 저장소에 있어 **개발자 도구로 누구나 바꿀 수 있습니다.** 실결제를 붙이기 전에 서버가 잔액·보상·소모를 검증하는 구조가 반드시 필요합니다 → [09](09-decisions-and-open-issues.md).

## 2. 카드 뽑기 — 컬렉션의 "상점" 탭

> 컬렉션 창은 **덱 편집 / 도감 / 합성 / 강화 / 상점** 5개 탭으로 나뉘어 있습니다. 상단의 주요 메뉴에서도 각 탭으로 바로 진입할 수 있습니다.

- **10회 결과 레이아웃**: 뽑기 전 예약 공간과 실제 결과는 모두 같은 5열×2행 그리드와 동일한 카드 폭을 사용합니다. 결과가 나온 뒤 `auto-fill`로 열 수가 늘어나 카드가 작아지면 안 됩니다. 폭 780px 이하에서는 예약 슬롯과 결과 모두 같은 2열 규격으로 전환합니다.

| 항목 | 내용 |
|---|---|
| 풀 | 출시 상태의 하수인·마법·함정 카드 전체. 희귀도 안에서는 카드마다 균등 |
| 확률 | 일반 75% · 희귀 20% · 전설 5% (카드 한 장 단위) |
| 10회 뽑기 | **마지막 1장은 희귀 이상 확정** (그 슬롯: 전설 10% / 희귀 90%) |
| 중복 | 같은 카드가 또 나오면 보유 수량 +1 |
| 전설 보장 | 전설이 50회 연속 나오지 않으면 51번째 결과를 전설로 확정. 전설 획득 시 연속 횟수 초기화 |
| 연출 | 가장 높은 희귀도 카드를 대표로 보여 주는 공개 연출 → 결과 카드 목록 |

### 쿠키조각

> 카드 뽑기의 기본 재화는 크래커입니다. 쿠키조각은 게임 승리와 유관 작품 젠돈 활동을 많이 한 유저에게 주는 보상성 추가 획득 수단입니다.

| 구분 | 프로토타입 값 |
|---|---:|
| 획득 | 캐릭터챗 젠돈 또는 Fate 게임 승리 |
| 게임 승리 보상 | 10개 |
| 카드 뽑기 1회 | 10개 |
| 카드 뽑기 10회 | 100개 |

- 젠돈과 게임 승리로 받은 조각은 출처나 작품과 관계없이 하나의 쿠키조각 잔액에 합산합니다.
- 별도 뽑기권으로 교환하지 않고 상점에서 카드 뽑기에 직접 사용합니다.
- 크래커 뽑기와 카드 풀·희귀도 확률·10회 보장·51번째 전설 보장을 공유하지만, UI에서는 크래커 기본 뽑기 아래에 보조 수단으로 구분해 표시합니다.
- 젠돈당 적립량과 지급 상한은 아직 확정 전입니다. 지급 이벤트 ID를 저장해 같은 보상이 재전송돼도 중복 지급하지 않습니다.

## 3. 카드 합성과 강화

컬렉션에서 `합성`과 `강화`를 서로 다른 탭으로 제공합니다.

### 카드 합성

- 서로 다른 카드를 섞거나 같은 카드를 중복해 여러 장 넣고, 재료와 다른 카드 1장을 만듭니다.
- 재료는 2장부터 최대 9장까지 넣습니다. 재료 칸은 3×3의 9칸으로 보이고, 카드별 원본 1장은 재료로 쓰지 않고 남깁니다.
- 재료 수별 기본 성공 확률: 2장 18%, 3장 25%, 4장 31%, 5장 36%, 6장 40%, 7장 43%, 8장 46%, 9장 48%.
- 연속으로 실패할 때마다 다음 성공 확률에 5%p를 더하되 최종 확률은 48%를 넘지 않습니다. 성공하면 보정을 초기화합니다.
- 성공하면 재료 중 가장 높은 등급 이상의 카드 1장을 받습니다(화면에 '성공 시 최소 등급'으로 표시). 성공·실패와 관계없이 넣은 재료는 모두 소모합니다.
- 결과 카드는 따로 칸을 두지 않고, 합성할 때 화면 가운데 연출로 보여 줍니다.

### 카드 강화

| 단계 | 재료 | 성공 확률 | 성공 결과 | 실패 결과 |
|---|---:|---:|---|---|
| 0차 → 1차 | 같은 0차 카드 3장 | 50% | 공격력 +0~1인 1차 카드 1장 | 0차 카드 1장 |
| 1차 → 2차 | 같은 1차 카드 3장 | 45% | 공격력 +0~2인 2차 카드 1장 | 1차 카드 1장 |
| 2차 → 3차 | 같은 2차 카드 3장 | 40% | 공격력 +0~2, 체력 +0~1인 3차 카드 1장 | 2차 카드 1장 |
| 3차 → 4차 | 같은 3차 카드 3장 | 35% | 공격력 +0~2, 체력 +0~2인 4차 카드 1장 | 3차 카드 1장 |

- 0차는 추가 능력치가 없는 미강화 카드입니다.
- 성공과 실패 모두 투입한 3장 중 2장을 소모하고 1장만 남깁니다.
- +0~2 추첨은 +0 60%, +1 30%, +2 10%이며, +0~1 추첨은 +0 60%, +1 40%입니다.
- 성공 카드의 보너스는 누적값이 아니라 해당 단계의 범위에서 새로 뽑은 최종값입니다.
- 능력치 보너스가 달라도 원본 카드와 강화 단계가 같으면 함께 재료로 사용할 수 있습니다. 실패하면 재료 카드 1장의 기존 보너스를 유지합니다.
- 강화해도 코스트, 효과, 성격 오라와 희귀도는 바뀌지 않습니다.
- 0차부터 4차까지 각 단계에는 해당 단계에서만 쓰는 전용 일러스트와 서로 다른 의상을 반드시 제공합니다.

### 강화의 제품 역할과 획득 루프

- 강화는 능력치 상승보다 좋아하는 동일 카드를 누적하고 4차 완성을 노리는 장기 수집 목표가 우선입니다.
- 낮은 강화 성공률과 +0 비중은 전투 격차를 제한하면서도 완벽한 카드를 만들고 싶은 반복 목표를 제공합니다.
- 목표 카드 재료는 상점에서 크래커 또는 공통 쿠키조각으로 카드를 직접 뽑아 확보합니다.
- 강화 화면은 다음 강화까지 필요한 동일 단계 카드 수와 쿠키조각 잔액을 표시하고, 부족하면 카드 뽑기 상점 또는 해당 캐릭터의 작품으로 이동할 수 있게 합니다.
- 도감은 캐릭터별 보유량과 현재 강화 단계를 함께 표시하고, 4차 달성 캐릭터를 `완결` 상태로 구분합니다.
- 전투 결과 화면은 승패와 보상을 먼저 보여 준 뒤 `티어 자세히 보기`와 `다시 하기` 중 하나를 선택하게 합니다. 결과 화면에서 도감으로 자동 이동하지 않으며, 캐릭터 완결 현황은 상단 도감 메뉴에서 확인합니다.
- 젠돈당 적립량과 일일·주간 상한은 아직 밸런스 확정 전입니다.

## 4. 카드 보유와 시작 카드

- 새 저장 데이터는 기본 덱을 구성할 수 있는 시작 카드를 보유한 상태로 시작합니다.
- 희귀·전설은 0장으로 시작하며 소환으로 얻습니다.
- 기본 덱은 하수인 30장, 마법 20장, 함정 10장으로 구성한 60장입니다 (2026-11-07, 이전 45/9/6). 컴퓨터 상대의 덱도 같은 구성입니다. 2026-11-09부터 기본 덱은 아래 오라 기본 덱 5종이고, 무작위 기본 덱은 `역전 체험덱 자동편성`과 저장 덱 복구에만 씁니다.
- 저장 데이터 v10부터 v9 이하 저장의 덱과 저장 덱 목록은 모두 새 기본 덱 하나(`덱 1`)로 교체합니다. (v9도 같은 방식으로 v8 이하를 교체했습니다.)
- 기본 덱 하수인 30장 중 12장은 소환사 압박 하수인(`pressure.*`)로 고정합니다 (2026-11-08). 자세한 내용은 `03-cards-and-effects.md`.
- 기본 덱의 마법 20장에는 `되돌리는 심판`, `반격의 방벽`, `거인 사냥`, `무게의 대가`, `생명 강탈`, `망자의 귀환`를 각각 1장 이상 확정 편성합니다.
- 덱 편집의 `역전 체험덱 자동편성`으로 기존 저장 덱도 같은 구성을 바로 적용할 수 있습니다.
- **오라 기본 덱 5종 (2026-11-09, 같은 날 PM 개정).** 불·물·나무·금속·대지마다 하나씩 있고 정의는 `03_card-data/sets/aura-decks.json`입니다.
  - 60장 = 하수인 40(덱 오라 20 + 다른 오라 4종 각 5장) + 마법 12 + 함정 8. 마법·함정은 다섯 덱이 같습니다(역전 마법 6종 포함).
  - 덱 오라 20장은 다섯 덱이 같은 비용 틀(압박 하수인 2종, 2비용 1종, 3비용 2종, 4비용 3종, 희귀 5·6비용 각 1종, 각 2장)을 씁니다. 다른 오라 5장은 그 오라 덱의 앞 5종(압박 하수인 2, 2비용 1, 3비용 2)을 1장씩 넣습니다. 소환사 압박 하수인은 덱마다 12장입니다.
  - 균형: 하수인 점수(공격 + 체력 + 효과 값 - 비용 기준치)로 덱 오라 20장 점수 차 2 이하, 40장 점수 차 4.5 이하, 평균 비용 차 0.2 이하를 테스트(`11_qa/regression/aura-decks.test.js`)로 지킵니다. 점수 식은 임시 기준입니다.
  - 기본 덱에 든 카드는 그 장수만큼 보유를 보장합니다(새 저장·기존 저장 모두).
- **같은 오라 하수인은 한 덱에 최대 20장입니다 (2026-11-09 PM).** 마법·함정의 오라는 세지 않습니다(이전: 마법·함정 포함 30장).
- **덱 편집 = 오라 5칸 (2026-11-09 PM).**
  - 덱은 항상 오라마다 하나씩 5개이고, 덱 편집 첫 화면 위에 오라 5칸(문양·오라 이름·덱 이름·장수)이 나옵니다. 각 칸에서 그 오라의 맞춤 덱을 편집합니다.
  - 새 덱·복제·삭제·오라 바꾸기는 없습니다. 덱 이름 바꾸기와 `○ 기본 덱으로 되돌리기`만 있습니다.
  - 기존 저장: 오라가 붙은 덱은 그 칸으로 갑니다(오라가 없던 옛 덱은 이름·하수인 비율로 오라를 붙입니다). 비어 있는 칸과 0장 덱은 그 오라의 기본 덱으로 채우고, 칸에 못 들어간 덱은 버립니다.
  - 전투 시작에서 성격 오라를 고르는 순간 그 칸의 덱으로 내 덱을 다시 섞고 시작 손패를 다시 뽑습니다. 그 덱이 60장이 아니거나 오라 상한을 넘으면 그 오라의 기본 덱을 씁니다.
  - 컴퓨터도 같은 방식으로, 컴퓨터 오라가 정해지면 그 오라의 기본 덱으로 다시 섞고 손패를 다시 뽑습니다.
- `?fixedStarter=1` 체험 시작 손패는 `battle-starter.json`에 등록된 카드 중 앞의 5장을 사용합니다.

## 5. 덱 편성 규칙

| 규칙 | 내용 |
|---|---|
| 크기 | **정확히 60장**이어야 저장됨 |
| 같은 카드 | 최대 **7장**, 단 보유 수량 이하 |
| 같은 성격 오라 | 최대 **30장** |
| 구성 가능 카드 | 하수인·마법·함정. 마법과 함정은 합계 최대 30장 (2026-11-07, 이전 15장) |
| 저장 덱 | 최대 6개. 이름은 최대 16자. 복제·삭제 가능, 메인 덱은 삭제 불가 |
| 저장 효과 | 저장 덱 중 하나를 메인 덱으로 지정. 대전 중 편집한 덱은 다음 대전부터 적용 |
| 셔플 | 같은 카드가 **3장 연속**으로 나오지 않게 섞음 (같은 카드 2연속까지는 허용) |
| 편집 방식 | 보유 카드를 눌러 추가, 덱 목록을 눌러 제거. 드래그 앤 드롭으로도 가능 (보유 → 덱 추가, 덱 → 보유 영역 제거) |
| 성격 필터 | 보유 카드 목록을 성격 오라별로 보기 |

> ⚠ 카드 데이터의 `deckLimit`(1~3장) 필드는 현재 **UI에서 쓰이지 않습니다** (전부 7장 규칙만 적용). 희귀도별 개별 제한을 적용하려면 별도 구현이 필요합니다 → [09](09-decisions-and-open-issues.md).

## 6. 저장 데이터 (알아야 할 위험)

- 키: `primal-collection-v1` (localStorage), 현재 형식 `version: 8`
- 내용: `crackers`, `cookieFragments`, `cookieRewardEvents[]`(최근 지급 이벤트 ID), `owned[]`(카드별 보유 수), `deck[]`(카드 번호 목록), `cardEnhancements`(카드별 1~4차 강화본과 능력치 보너스), **`cardIds[]`(저장 당시의 카드 ID 목록)**
- 보유 수·덱은 카드 "번호(순서)"로 저장하지만, **저장할 때마다 `cardIds`를 함께 기록**합니다. 불러올 때 현재 카드 목록과 다르면(카드 삭제·삽입·순서 변경) **cardId 기준으로 자동 정렬**합니다(`remapSavedByCardIds`). 그래서 이제 카드를 중간에서 지우거나 끼워 넣어도 기존 유저의 보유 카드·덱이 다른 카드로 바뀌지 않습니다.
  - 삭제된 카드는 보유·덱에서 빠지고, 새로 생긴 카드는 0장으로 시작합니다. 덱이 60장에서 모자라면 자동 보정됩니다.
  - `cardIds`가 없는 예전 저장본은 기존 번호 마이그레이션(v5→v6→v7)을 거친 뒤 다음 저장부터 `cardIds`가 붙습니다.
  - 그래도 **새 카드는 목록 맨 끝에 추가**하는 것이 가장 안전합니다.
- 버전이 5 미만이면 저장 데이터를 초기화합니다(크래커만 유지).
