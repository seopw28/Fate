# AI Effect Production Methodology

## 목표

AI 생성 결과를 일회성 이미지가 아니라 반복 제작 가능한 스킬 이펙트 자산으로 만든다. 화려함보다 전투 정보의 판독성, 카드 오라과의 일관성, 낮은 사양에서의 안정성을 우선한다.

## 제작 단계

1. 효과 사양 작성
   - `specs/effect.schema.json`을 따르는 JSON을 만든다.
   - 발동 원인, 대상, 시작·정점·종료 프레임과 화면 점유 범위를 고정한다.
2. 프롬프트 작성
   - `prompts/base-prompt.md`를 복사해 효과별 차이만 채운다.
   - 특정 게임, 작가, 캐릭터의 스타일 모방은 금지한다.
3. AI 원본 생성
   - 투명 배경의 단일 모티프 또는 스프라이트 시트를 우선한다.
   - 생성 모델, 날짜, 프롬프트와 입력 이미지를 함께 기록한다.
4. 게임용 가공
   - 알파 가장자리, 색 번짐, 프레임 정렬과 크기를 정리한다.
   - 원본은 `generated/`, 가공본은 `processed/`에 둔다.
5. VFX Lab 검수
   - 밝고 어두운 카드, 작은 전장 카드, 영웅 HP 바 위에서 각각 재생한다.
   - 일반 모션과 `prefers-reduced-motion` 대체안을 모두 확인한다.
6. 승인 및 배포
   - `review/quality-checklist.md`를 통과한 후보만 `approved/`로 승격한다.
   - 최종 파일을 `06_assets/vfx/`로 복사하고 레지스트리의 상태를 `approved`로 바꾼다.

## 생성 전략

### 1. 절차형 우선

보호막, 회복 링, 궤적, 화면 플래시처럼 형태가 단순한 효과는 CSS·Canvas·파티클로 만든다. 색상, 속도와 크기를 쉽게 조절할 수 있고 파일 용량이 작다.

### 2. AI 텍스처 결합

화염, 연기, 물결, 마법진처럼 표면 디테일이 중요한 효과는 AI로 투명 텍스처를 만들고 절차형 모션 위에 합성한다. AI가 타이밍을 결정하지 않게 하고 엔진이 타이밍을 제어한다.

### 3. 스프라이트 시트 제한 사용

형태 변화가 핵심인 폭발이나 소환 연출에만 사용한다. 프레임마다 중심점과 외곽 크기가 흔들리면 승인하지 않는다.

## 공통 성능 예산

- 일반 스킬: 1.2초 이내, 동시 파티클 24개 이하
- 궁극기: 2.5초 이내, 동시 파티클 48개 이하
- 단일 텍스처: 512×512 이하
- 스프라이트 시트: 총 2048×2048 이하, 30프레임 이하
- 모바일 후보 자산: 효과 하나당 500KB 이하
- 저사양 모드: 텍스처 1개와 불투명도·크기 변화만으로 의미 전달

## 품질 원칙

- 효과가 가려도 카드명, 공격력, 체력은 읽을 수 있어야 한다.
- 피해, 회복, 보호막과 상태 이상은 색상뿐 아니라 형태와 움직임도 달라야 한다.
- 공격 효과는 대상 방향을, 회복·강화 효과는 소유 주체를 명확히 보여야 한다.
- 화면 전체 플래시는 120ms 이하로 제한하고 반복 점멸을 피한다.
- AI 산출물에는 글자, 로고, 인물, 카드 프레임이 포함되면 안 된다.

## 장기 자동화

1. 효과 사양에서 생성 프롬프트 초안을 자동 생성한다.
2. 같은 사양으로 4개 후보를 생성하고 VFX Lab 비교 페이지를 만든다.
3. 알파, 파일 크기, 해상도와 프레임 중심 흔들림을 자동 검사한다.
4. 승인 후보만 레지스트리와 빌드 매니페스트에 반영한다.
5. 게임 리플레이 캡처로 실제 판독성을 회귀 비교한다.
